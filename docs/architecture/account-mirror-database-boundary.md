# Account mirror database boundary (staged, not enabled)

The owner mutation outbox is internal only. `MIRROR_FEED_ENABLED` must remain unset or `false`; setting any other value blocks deployment. The gate in `infra/secrets.ts` deliberately reports unresolved runtime privilege and writer coverage, even if all three role secrets are populated. Do not flip its assertions based only on provisioning: DocumentDB roles cannot require an outbox event in the same transaction as a source write.

## Operator provisioning (per stage)

1. Create separate DocumentDB users for application, worker and migration. Grant each only the required database/collection actions after a workload-by-workload audit; migration may need index/DDL privileges, but the two runtime identities must not inherit those privileges or the legacy admin identity. Verify with negative write/DDL tests against a disposable stage and positive application, worker and migration smoke tests. No production permissions are modified by this change.
2. Set `MONGODB_APP_URI`, `MONGODB_WORKER_URI`, `MONGODB_MIGRATION_URI` as per-stage SST secrets using `sst secret set <NAME> --stage <stage>` with a value supplied securely to the operator (never in source, command logs or CI output). Each URI must carry its own database identity and the correct stage database. Rotation and rollback are operator actions. The migration Lambda alone links the migration secret. While unset it uses the legacy URI; a future cutover can set `MIRROR_REQUIRE_DATABASE_ROLES=true` on the migration Lambda to refuse legacy fallback after migration and seeding paths are audited.
3. Inventory all consumers of `MONGODB_URI`, including client API Lambdas, workers, ECS services, self-host entrypoints, scripts, preview cleaner, seeder, and any external jobs. Move each to its matching role and remove the legacy credential from all runtime links, ECS task secrets and environment/shim paths. Verify the deployed resource bindings and use a disposable role simulation to demonstrate that runtime roles cannot access privileged collections or management commands. A distinct URI string alone proves neither a distinct principal nor least privilege.
4. Migrate each included record writer to `writeOwnerMutation` with its source mutation on the same session; cover owner transfers, hard/soft deletes, raw-driver and bulk operations, imports, scripts, and maintenance. `packages/scripts/src/mirrorWriterInventory.ts` enumerates syntactic direct write calls in client, workers and scripts; its tests keep those trees visible. This is a conservative call-site inventory, not a proof of model ownership, dynamic methods, transitive services, third-party code, or outbox transaction participation. Review each call and maintain a verified per-writer mapping before allowing readiness. `OWNER_MIRROR_UNINSTRUMENTED_RECORDS` remains nonempty; snapshot and immutable byte-reference fencing also remain open.
5. Only after full coverage, prove bootstrap plus incremental replay equals a fresh export under concurrent writes, verify negative privilege tests on hosted DocumentDB, and separately review the feed gate. Keep the feed disabled until all runtime links and included writers are verified. Do not assert `databasePrivilegesEnforced` merely because users exist.

The config accepts staged secret names without exposing values; the migration Lambda may use its dedicated role today when configured. The existing shared `MONGODB_URI` remains widely linked, so there is **no effective isolation boundary yet**. The read gate and deploy opt-in gate intentionally remain closed.
