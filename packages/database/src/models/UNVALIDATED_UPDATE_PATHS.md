# Constrained paths written by update calls

Mongoose runs schema validators (`enum`, `maxlength`, `minlength`, `min`, `max`, `match`) on `create` and
`save` only. An update (`findOneAndUpdate`, `updateOne`, `updateMany`, `findByIdAndUpdate`) reaches them only
when the call passes `runValidators`, or when the model gates the path in a pre-update hook. Any other
update that writes a constrained path is protected by whatever sits in front of it, or by nothing.

This file lists every constrained schema path that a literal update call under `src/models` writes, and the
gate that actually protects it. `src/__test__/unvalidatedUpdatePaths/unvalidatedUpdatePaths.test.ts`
re-derives the list from source on every run and fails when:

- a writer of a constrained path appears with no row here, or a row no longer matches a writer;
- a writer the table gates with `runValidators` drops it (or one starts passing it);
- a writer the table gates with `literal` starts storing a runtime value, or a literal falls outside the schema;
- a pre-update hook gate stops rejecting an out-of-constraint value;
- an in-package `ref` stops naming a symbol that exists.

When the test fails, it prints the row to add; set its gate as below.

## Gates

| Gate | Meaning | Ref |
|---|---|---|
| `schema` | Mongoose itself rejects the value on this write. | `runValidators`, or the pre-update hook that gates the path |
| `repository-check` | The writer only stores allowed values: source literals, a clamp, a slice, a constant map, a `$cond` between literals, a `$pull`/`$pop` that adds nothing. | `literal` when every stored value is a source literal (checked against the schema), else the writer or helper |
| `route-schema` | The writer passes the value through, but every production caller derives it from a request schema or from constants. | The schema or constant at the caller |
| `none` | At least one caller can store a value that only a TypeScript type checks, or the writer has no production caller to rely on. | (empty) |

`route-schema` and non-literal `repository-check` rows record a reading of the callers at the time of the
audit; the test checks only that an in-package ref still exists. A new caller of a `route-schema` writer
can silently turn it into `none`.

## Scope

- Literal update calls only. A call whose update document is a variable or a spread is not read, so
  `BaseRepository.update` / `updateGuarded` / `updateMany` (db-core), which `$set` a caller-built patch
  with no validators, is not enumerated per path: it reaches every path of every model with a repository.
- Mongoose model calls only. Raw-driver writes (`this.model.collection.updateOne(...)`) and `bulkWrite` skip
  validators and pre-update hooks alike, and are not scanned.
- Writers under `packages/database/src/models` only. Direct model writes in `apps/*` and `b4m-core/*` are
  not scanned.
- `$unset`, `$rename`, `$currentDate`, `$pull`, `$pullAll` and `$pop` store no caller-chosen value, so they
  are not counted. `$inc` and `$mul` are, with a computed (non-literal) result, as is a pipeline `'$field'`
  reference.
